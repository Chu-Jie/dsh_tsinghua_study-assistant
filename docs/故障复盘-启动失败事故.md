## 二、方法论教训（按严重度）

这一节回答「为什么 106 项自测全绿，代码依然炸掉了整个应用」。

1. **测试用了过于宽松的替身。** `tests/host.test.js` 自造的假 ctx 里，
   `tools.register` 只把定义 push 进数组，**没有跑真实现的校验**。
   于是我只验证了「`output.render` 是函数」这种浅层形状，漏掉了注册路径上真正的关卡。
   → 修法：把官方校验规则**照抄进测试**（假 ctx 在注册时即抛），并让
   `tools/verify-installed.mjs` 直接 `import` **生产版** `assertSupportedJsonSchema` 再跑一遍。
   *这是本次事故最核心的教训：用一个比真身宽松的替身去测真接口，通过只能证明替身通过了。*

2. **把「扫过源码」当成「验证过行为」。** 我确实打开过 `dsh-tools` 的 `register`，看到了
   `assertSupportedJsonSchema(output.schema)` 那一行，却只核对了自己关心的上一行，
   把校验当成了背景噪音。
   → 教训：读契约要读**整个函数体**，尤其是自己没写、却一定会被调用的断言。

3. **风险分配错了地方。** 我反复声明「客户端渲染是我无法自证的环节」，
   而真正的炸点在**宿主侧 schema** —— 那本是我完全能验证的。我把注意力放在了
   自己觉得难的地方，而不是失败代价最大的地方。

4. **`application: "restart-required"` ≠ 已生效。** 运行中的进程不会重载 ESM 模块代，
   我却连续几轮在「包已落地 = 已生效」这个错误前提上做判断。

5. **用 shell 改文本文件损坏了 UTF-8 中文。** 做变异测试时用 `Set-Content`，
   文件被写成 ANSI，造成 10 项测试以语法错误失败 —— 那是自伤，不是有效证据。
   → 教训：改文件只用编辑工具，不要用 shell 重写文本。（与 §三 同源。）

6. **在客户端 inspect 查询上连踩三次。** `platform: "client"` 的查询需要浏览器页面回话，
   页面不应答就一直挂起（`Client inspect query was cancelled`）。第一次就该换路径。

7. **做了重复劳动。** 我写了一份复盘后才发现，15 分钟前已有另一个会话写了更完整的版本。
   → 教训：动笔写总结前，先列目录看有没有现成文档。

## 三、【已更正】中文路径并没有编码隐患 —— 那是我误判的显示假象

**本节原结论作废，保留更正过程本身作为教训。**

我曾在 `%APPDATA%\dsh-desktop\harness\recovery\plugin-removals.json` 里看到
插件来源路径是乱码，于是写下「中文路径有编码隐患」的结论。**这是错的。**

用 `tools/diag-encoding.mjs` 直接读码点验证后：

```
sourceSpec 码点长度 = 20
前 24 个码点(hex) = 44 3a 5c 5927 5b66 5c 5927 4e8c 4e0a 5c 4f5c 4e1a 5c 5f 63d2 4ef6 5c 5b66 4e60 53f0
包含 U+5927/U+5B66（「大学」）      : true
包含 U+FFFD（替换字符，真损坏标志）  : false
包含「澶」U+6FB6（GBK 误读典型字）   : false
```

`5927 5b66` 就是「大学」、`5b66 4e60 53f0` 就是「学习台」——**文件里存的是完全正确的 UTF-8**。
我之前看到的乱码，只是 **PowerShell 控制台按系统代码页（CP936）渲染**的结果。
同样的假象也出现在 `Get-Content package.json` 上：`meta.title` 打印成 `澶у鐢熷涔犺緟鍔╃郴缁?`，
但 `JSON.parse` 之后码点是 `5927 5b66 751f 5b66`（大学生学），文件毫发无损。

**教训（比原结论更有价值）**：
> 不要用 shell 的**文本输出**判断文件编码。控制台代码页会伪造乱码。
> 判据要用「读字节 / 读码点」：`JSON.parse` 后取 `codePointAt`，或检查是否含 `U+FFFD`。

这条误判的代价是我把它写进了一份复盘，并据此建议迁移路径——一个**基于假象的建议**。

**仍然成立的部分**：`用 Set-Content 改文本文件会真的损坏 UTF-8`
（本会话里我用它写 `client.js`，中文被写成 ANSI，10 项测试以语法错误失败）。
那是真损坏，因为写回的字节确实变了。改文件请一律用编辑工具。

## 四、出事时的快速恢复清单

权威文档 §十 有完整的排障命令；这里只放**最短恢复路径**，按顺序做：

1. **看日志定位**：`%APPDATA%\dsh-desktop\logs\harness.log`
   搜 `startup failed` / `plugin failures` / `web boot` / `frontend plugin recovery`。
2. **应用关不掉**（启动失败后常见）：结束**主进程**，不是 `--type=renderer` 子进程：

   ```powershell
   taskkill /F /IM "DSH Desktop.exe"
   ```

   任务管理器里要认**名字就叫 `DSH Desktop`（无 `--type=` 后缀）**的那个。
3. **只想让它先能开**：把 `%APPDATA%\dsh-desktop\harness\profiles\web\cordis.patch.yml`
   里对应那行改成 `disabled: true`（或整段删掉）。注意：删掉行却留着
   `package.json` 的 `bundles` 条目会报 `patch: entry "..." not found`，两边要一起改。
4. **彻底移除**：从 `profiles\web\package.json` 的 `dsh.profile.bundles` 与 `dependencies` 删掉，
   再删 `profiles\web\node_modules\@local\<包名>`（以及 `.generations\live\` 下对应目录）。
5. **安全模式里 pnpm 不可用**，`install_bundle` 必然失败（`'pnpm' 不是内部或外部命令`）。
   此时只能**直接改** `.generations\live\<id>\node_modules\@local\<包名>\` 里的文件 ——
   已确认 `dsh-app-boot` 不做内容哈希校验（连 `createHash` 都没有），改了下次启动即生效。
6. **别忘记**：`杀 harness 会连带关掉桌面端`（权威文档 §六 的实测观察）。

## 五、写 DSH 插件的检查清单（浓缩）

**工具 schema**
- [ ] `type` 只用**单一字符串**；禁止 `['string','null']` 这类数组
- [ ] 可空字段**不声明**，靠 `additionalProperties: true` 放行，render 侧处理 `null`/`undefined`
- [ ] 不用子集外关键字（子集：`type`/`oneOf`/`properties`/`required`/`additionalProperties`/`items`/`enum`/`const` + 注解）
- [ ] `required` 里每个名字都在 `properties` 里声明过
- [ ] 写完跑一遍**生产版** `assertSupportedJsonSchema`

**测试**
- [ ] 假 ctx 实现真实现的**全部**校验，不做「够用的假货」
- [ ] 每个「两个分开写的字符串必须相等」的契约都要断言（如槽位 key == 标签类型 id）
- [ ] 关键断言做**变异验证**：故意写错，确认测试真的会红

**安装与验证**
- [ ] `restart-required` ≠ 已生效，**必须重启**后再验证
- [ ] 重启后同时看两处：`harness.log` 的 `plugin failures`，以及页面侧 `web boot: N entry did not activate`
- [ ] 覆盖安装件前先整目录备份
- [ ] 开发期优先用**非 required 行**安装，避免「改一行 schema 就把桌面端打进安全模式」
      （权威文档 §五 的结论性教训：对 required 行，「能启动」本身就是必须验证的契约）

## 六、本会话对根因 B 的一条线索

根因 B 是在**旧版 `client.js`** 下观测到的。旧版右侧栏注册用的是
`key: 'study-detail'`，而它注册的标签类型 id 是另一个字符串 —— 按官方契约
（`sidebar.right.pane.tab` 的 key 必须是标签类型的 `id`），这个 key 永远不会被派发。
本会话已把 key 改为与标签类型 id 一致（`study-assistant/detail`），
并补了三条契约测试与变异验证。

**但这只是线索，不能当作根因 B 已解决**：权威文档 §4.3 的离线复现用的是修好后的版本，
且结论是「6 处注册本身不是原因」。所以根因 B 仍需按 §4.6 用 CDP 现场抓真实异常。
