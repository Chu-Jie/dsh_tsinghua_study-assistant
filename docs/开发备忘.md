# 开发备忘

给**改这个仓库的人**（包括几个月后的自己）的踩坑清单。不是教程，全是「当时不知道、后来被咬过」的具体点。
接口契约见 [`接口契约.md`](接口契约.md)，模块划分见 [`设计说明.md`](设计说明.md)。

---

## 一、改动的固定流程

```bash
cd <本仓库>
# 1. 只改源码，不直接改产物
# 2. 如果动了 client.full.js：把产物同步回来（默认方向是反的！）
node tools/sync-client-full.mjs --reverse   # client.full.js → client.js
node tools/sync-client-full.mjs --check     # 逐字一致才算同步成功
# 3. 跑测试
npm test
# 4. 装机验收（验证的是「已装进 profile 的那份」）
npm run verify:installed
# 5. 重启宿主 + 刷新页面
```

三条容易忘的：

- **`--reverse`**：同步脚本的默认方向是 `client.js → client.full.js`，忘了加会把你的编辑整段冲掉。
- **重启宿主**：宿主不会热重载插件主体。只改 `client.js` 且启用了客户端热重载时才可能免刷新。
- **`verify:dsh` 不是 CI**：三个校验脚本要求本机装着 DSH 的生产包产物，找不到会报错/跳过；CI 只跑 `npm test`。

## 二、会让宿主启动失败的坑（最高优先级）

### 1. 工具 schema 里不能出现 `type` 数组

```js
// ✗ 让整个宿主启动失败
parameters: { type: 'object', properties: { foo: { type: ['string', 'null'] } } }
// ✓
parameters: { type: 'object', properties: { foo: { type: 'string' } } }
```

宿主的 `assertSupportedJsonSchema` 会抛 `JsonSchemaError: unsupported ...`，**插件激活失败**，
而错误日志是宿主打的，很容易被当成「DSH 坏了」。用完 `null` 请改成「可选 + 默认值」。

### 2. 配置 schema 必须覆盖每个键

`Config` 是手写同步 schema：**配置里出现 `Config` 没声明的键，或类型不符，都会激活失败**。
加配置项时三处一起改：`Config` 声明、默认值、文档（`README.md` 的配置表）。

### 3. 相对路径的 `dataDir` 会落到「你以为不是」的地方

数据目录解析成相对路径时，基准是**宿主进程的 cwd**，而不是仓库或配置所在目录。
于是插件建了一套空数据、界面什么都没有，而日志里一切正常。
`dataDir` 一律解析成绝对路径；默认值用 `path.join(os.homedir(), 'study-assistant-data')`，别硬编码盘符。

### 4. 路由注册必须用 `kind: 'prefix'`

宿主的路由匹配是「先精确匹配，再按前缀匹配」。用 `kind: 'exact'` 注册时，
`/api/study-assistant/state` 这类子路径根本到不了你的 handler。
另外：**不要新增精确路由**，也不要另造路由表。

## 三、数据层

### 5. 损坏的文件绝不能当空数据重写

```js
const read = await store.readDocument(key);
if (!read.ok && read.reason !== 'missing') return sendJson(res, 409, { error: read.reason });
const doc = read.ok ? read.doc : defaultDoc(key);
```

漏了这一步，用户某个手抖写坏的 JSON 会被下一次自动写入**整个覆盖成空数据**，备份也救不回最新状态。

### 6. 批量写不能静默截断

曾写成 `items.slice(0, 500)`：超过 500 条时只改了前 500 个，调用方却收到 `ok:true`。
正确做法是**超限直接报错**（`400 too-many-items`），让调用方知道要分批。

### 7. 截断与去重记号的顺序

所有字符串过 `normalizeName` 会**截到 120 字**。任务备注里同时要放 learn 去重记号 `[learn:<key>]` 与归档标记，
所以「追加」时必须判断长度：能塞末尾就塞末尾（保住去重记号），塞不下才把新标记提到开头。

### 8. `/state` 里 `ok` 要放在展开之后

`readAll()` 自带一个 `ok` 字段（值为「所有问题都只是 missing」）。写成 `{ ok: true, ...all }` 会被它覆盖，
于是一份文档损坏时客户端收到 `ok:false` 却没有 `error` 字段，面板对**所有**文档一起报「读取失败」。

### 9. 乐观并发不能只看「服务端刚读到的 hash」

`expectedHash` 省略时用刚读到的 hash 仍然有价值（挡住「读之后被外部改」），
但客户端应当把它看到的 hash 回传——否则两个面板同时开着时，后保存的会覆盖先保存的而不报冲突。

## 四、HTTP 层

### 10. 二进制请求体不能用文本读取

`readBody(req, { binary: true })` 不做 UTF-8 解码。若把 WAV 当字符串读再拼回 Buffer，
每个非法 UTF-8 字节都会被替换成 `EF BF BD`，音频就废了，而长度「看起来对」，很难查。

### 11. 返回 413 之前要把请求体排空

直接 `res.end()` 会让客户端看到连接被重置（`ECONNRESET`）而不是 413。
读完丢弃再回，客户端才能正确显示「太大了」。同理：`readBody` 超限后继续读，只为排空。

### 12. 写请求的三道闸顺序固定，且要在解析体之前

`originAllowed` → `Content-Type` → `X-Study-Request`。反过来先解析体，恶意/跨站请求就能白嫖一次大体积解析。
`skipContentType` 只有 `/reset-doc` 与 `/lecture/chunk` 两处，不要扩散。

### 13. 音频有自己的体积上限

16 kHz 单声道 PCM16 每秒 32,000 字节，60 秒就 1.92 MB，会被通用 1 MiB 上限 413 掉，
而错误码只有 `too-large`，看不出是「音频太长」。所以音频单算：`44 + 120 s × 32000 + 4096`。

### 14. 音频必须是规范 WAV

DSH 的 `speechToText` 逐字段校验：**16 kHz / 单声道 / PCM16**，不符合直接抛
`Audio must be a canonical 16 kHz mono PCM16 WAV recording`。
录音页与服务端共用 `lib/lecture/wav.js` 的同一套打包/校验函数，别在两处各写一份。

### 15. 定时器/子进程不要放在 handler 构造期

`createApiHandler` 在测试里被反复调用。构造时起定时器 = 每个用例漏一个 interval。
由 `index.js` 用 `ctx.effect(() => { const t = setInterval(...); return () => clearInterval(t); })` 起。

## 五、面板（client）

### 16. 只用主题令牌，不写死颜色

颜色一律用 `--dsw-alias-*`（`--dsw-alias-bg-base`、`--dsw-alias-label-primary` 等），
不留十六进制色值。硬编码的样式在深色主题下会瞎，而且过不了主题令牌审计。

### 17. 面板状态不要落盘

页签、搜索词、筛选、展开分支都放模块内存。落盘会带来「上一次的筛选把这一次的列表藏光」这类灵异问题。

### 18. 面板渲染要能吃坏数据

`npm run panel:smoke` 专门喂三种坏数据（空、`null` 混入、无大纲）。渲染时对每个字段做兜底，
不要把 `undefined`、`NaN`、`[object Object]` 直接印到界面上。

## 六、平台侧（网络学堂）

### 19. 只带 Cookie 会被 403

页面接口只要 Cookie，但**数据接口还需要 CSRF 头**（值从同名 Cookie 取）。
「先只发 Cookie，403 且有 CSRF cookie 再补头重试一次」只是兜底，不要依赖——课程与作业列表全走需要 CSRF 的那一侧。

### 20. Cookie 是缓存，浏览器才是凭据持有者

会话 Cookie 由服务端空闲超时控制；长命的是单点登录的「信任浏览器」凭证，存在专用浏览器 profile 里。
所以自愈顺序是：先看浏览器在不在 → 从浏览器取票 → 再同步。**不要**把「要人工登录」当成故障反复重连，
它只是一条冷却期的封条。

### 21. 凭据不进白名单

`网络学堂.json` 刻意不在 `DOC_FILES` 里：它不会进 `/state`、不进备份包、不会被 `/reset-doc` 清掉。
写它要原子写 + `mode 0o600`，日志与响应体里都不能出现 Cookie。

## 八、出事时怎么定位

| 现象 | 先看 |
|---|---|
| 宿主起不来 / 插件没激活 | 宿主日志里有没有 `JsonSchemaError`、配置校验 `issues`；临时把配置减到最小（只留 `dataDir`）再试 |
| 面板空白 | `npm run panel:smoke -- --data <dataDir>`；再查 `/health` 与 `/state` 的 `problems` |
| 数据「不见了」 | `study_status` 看 `dataDir` 是否是你以为的那个；`/health` 看每份文件 `exists/bytes`；再看 `备份/` |
| 保存报 409 | 另一处刚写过（另一个宿主窗口、手改、脚本）。刷新取新 hash 再存，**不要**忽略提示重试 |
| 同步拿不到数据 | `/learn/status` 与 `/learn/session`；Cookie 是否整条、CSRF cookie 在不在、冷却期是否过了 |
| 讲解/问答报 502 | `llm-empty-response` 可重试；`llm-unavailable` 是宿主没挂模型接口 |
