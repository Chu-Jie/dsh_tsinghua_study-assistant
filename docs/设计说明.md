# 设计说明

本文讲**为什么这样拆**：模块边界、数据怎么流、以及那些看起来可以更简单的地方为什么没简化。
接口层面的字段约定见 [`接口契约.md`](接口契约.md)，用法见 [`使用手册.md`](使用手册.md)。

---

## 一、目标与约束

一句话：**一个能长期自用的学习辅助插件，数据是普通文件，坏了自己能修。**

由此定下的硬约束：

| 约束 | 原因 |
|---|---|
| 零运行时依赖 | 装进别人机器只需一次 `npm install link:`；没有原生模块、没有 peer 版本地狱。Node ≥ 22 的内置 `fetch` / `node:test` / `node:sqlite` 够用 |
| 数据是 JSON 文件 | 能 `git diff`、能手改、能整包导出；出问题能直接看文件而不是查数据库 |
| 不另起端口 | 复用宿主 Web 服务器，不占端口、不额外暴露监听；同源约束直接复用宿主那套 |
| 不写 `Set-Cookie` | 面板与接口同源，凭据不出服务端 |
| 可测 | 所有模块都能在 Node 里直接跑；不在 import 期起定时器、开进程、读环境 |

## 二、模块地图

```
index.js                  443 行  宿主入口：配置 schema（Config）、apply()、注册路由/工具/定时器
lib/
  core.js                 896 行  纯领域逻辑：日期与周次、GPA、概览、文档形状与校验、id、归一化
  store.js                279 行  存储层：原子写、sha256、备份轮转、冲突检测
  api.js                 3433 行  HTTP 层：三道闸、44 条路由、所有 handler
  backup.js               118 行  纯函数：打包 / 校验和 / 验包
  deliverables.js         443 行  提交件扫描：文件名解析、任务唯一匹配
  homework.js             339 行  作业流：取字 → 分题 → 台账
  questions.js            363 行  题目：切分、答案对齐、草稿确认、校验
  knowledge.js            245 行  织网：候选 → 节点（合并同名/别名，只补空字段）
  knowledge-explain.js    247 行  讲解/问答的提示词与缓存解析
  kp-notes-export.js      373 行  网络 + 题目 → 笔记镜像
  pdf-text.js             217 行  PDF 文字层抽取
  learn.js               1183 行  网络学堂：抓取、解析、匹配课程、生成任务
  learn-browser.js        640 行  专用浏览器 + CDP 客户端（取 Cookie / 拉作业详情）
  learn-detail-cache.js   123 行  作业详情缓存（任务详情.json，TTL 3 分钟）
  learn-keepalive.js       93 行  会话心跳（8 分钟一跳，落日志不落票）
  lecture/                       听课：wav 校验、切片、ASR、会话、笔记、报告、面板、导入
client.js                403 KB  随包发布的面板（构建产物形态）
client.full.js           403 KB  可编辑的那份，`tools/sync-client-full.mjs` 保证与 client.js 逐字一致
tools/                         命令行脚本（织网 / 大纲 / 体检 / 分题 / 浅表导出 / 装机验收 / 同步校验）
tests/                         37 个 node:test 用例文件，536 项
```

依赖方向是**单向**的：

```
index.js ─→ api.js ─→ core.js / store.js / backup.js / deliverables.js / knowledge*.js / learn*.js / lecture/*
              │
client.js ────┘（只通过 HTTP 说话，不 import 任何 lib 模块）
tools/*.mjs ──→ core.js / store.js（不经过 api.js）
```

`lib/api.js` 是唯一知道 HTTP 的地方；`lib/core.js` 不认识 `req`/`res`，也不知道文件在哪；
`lib/store.js` 只认「key → 文件」，不认识业务字段。所以工具脚本与 HTTP 接口能共用同一套落盘逻辑，而面板只能走 HTTP。

## 三、数据怎么流

### 面板

```
client.js ──fetch──> /api/study-assistant/* ──> handler ──> store ──> <dataDir>/*.json
    ↑                                                                    │
    └──────────────── { ok, doc, hash } ─────────────────────────────────┘
```

- 读：`GET /state`（可带 `?doc=`）拿文档 + 每份的 `hash`；
- 写：`POST /mutate` 必须带 `expectedHash`（可省，省略则用服务端刚读到的），冲突回 `409`；
- 面板**不缓存跨会话状态**：页签、搜索词、筛选、展开到哪一分支全在内存，重启即回默认。

### 会话里的 agent

只挂两个**只读**工具：`study_status`（健康）、`study_overview`（当前学期 / 今日课程 / 临近 DDL / GPA）。
要改数据时 agent 走 `/mutate`（同样过校验与冲突检查），**不给它一个「随手改」的工具**——
写入口越少，误改面越小，也更容易审计。

### 平台侧（网络学堂）

```
面板 ─POST /learn/connect{cookie}─> learn.js ─> 平台接口（Cookie + CSRF 头）
                                        │
learn-browser.js（专用浏览器 profile）───┘  取 Cookie / 弹登录窗口 / 拉作业详情
                                        │
                                    写 网络学堂.json（0o600，不进白名单）
```

### 听课

```
浏览器录音 ─WAV 16k/mono/PCM16─> /lecture/chunk（二进制 body，专用上限）
   └─> wav.js 校验 ─> ASR（宿主 speechToText）─> session（转写窗口、点名匹配、去重）
        └─> notes（写好笔记）/ report（课后报告）
```

### 工具脚本

`tools/knowledge-weave.mjs`、`knowledge-outline.mjs`、`analysis.mjs`、`split-homework.mjs` 等都**直接调 `lib/`**：
读 JSON → 计算 → 走 `store.writeDocument` 落盘（同样会先备份旧版）。

## 四、存储层的四条安全线

`lib/store.js` 只做一件事：把「写一个 JSON 文件」变成**可恢复**的操作。

1. **原子写**：写 `*.tmp` → `fsync` → `rename`。断电最坏是留下一个 `.tmp`，不会出现半个 JSON。
2. **内容哈希**：`hashOf(key)` = sha256(文件内容)。写请求带 `expectedHash`，不等就 `409 conflict` 而不是覆盖。
3. **备份轮转**：覆盖前把旧版复制进 `备份/`，按 `backupKeep`（默认 10）淘汰最旧的。
4. **损坏保护**：读到的文件过不了 `validateDoc` 就**拒绝在其上增量修改**（`409`），
   既不「当作空数据重写」，也不静默跳过。

### 为什么不用事务

每份文档独立、写前都有备份、写失败逐份回报。加事务需要跨文件锁与回滚日志，
收益是把「写一半」变成「全不写」——但备份已经覆盖了恢复需求，而回滚会再写一次数据，风险反而更大。
所以 `/backup/restore` 明确**不回滚**：先验后写已经堵死「坏包写半截」。

## 五、几个关键取舍

### 1. 十一份文档，而不是一份大 JSON

一开始是一份，很快发现两类内容体积差三个量级：知识点网络几十 KB，知识点详解内容库可到 MB。
混在一起意味着面板每次打开都要搬一遍几 MB。于是按**「身份 / 内容 / 索引」**拆开：

- `知识点网络.json`：有哪些节点、掌握到什么程度（小、常改）；
- `资料分析.json`：节点讲了什么（大、少改）；
- `知识点大纲.json`：教材目录骨架（中等、只在重解析时改）。

代价是「一个节点」的信息分散在三处，所以要有一致性检查（`knowledge:audit`）与两处专门的写入口。

### 2. `lib/api.js` 一个 3400 行的文件

反直觉，但这是刻意的：**所有请求都要过同样的三道闸、同样的体积上限、同样的错误码规范**。
如果按 family 拆成 8 个文件，这些「必须一致」的规则就得复制 8 份或者抽出一个中间层——
而中间层很快就会长出「有的 handler 忘了调 `writePreflight`」这类漏洞。
现在它是一串 `if (rest === '…')`，一眼能看出有没有地方漏了守卫。

代价是可读性与合并冲突，靠两条纪律兜：
① 加路由只能是一行 `if`，不许造路由表；② `tests/host.test.js` 从 handler 源码反推路由清单，
新增路由不同步注册会被测试抓出来。

### 3. 讲解有两套（内容库 + 现场生成）

- `资料分析.json` 里的 `points[].explain` 等字段：**提前算好**、点开秒看，可以人工审、可以进版本库；
- `讲解缓存/*.md`：**现场调模型**生成的三个档位（助教推导 / 考前速通 / 只给提示），带 frontmatter 与 `stale` 标记。

两套不合并，因为它们是不同的东西：前者是「内容」，后者是「针对某个节点的一时一事」。
面板会分开报「有详解 X · 只有旧讲解 Y · 都没有 Z」，用户一眼知道下一步该补哪种。

### 4. 只读工具 + 单一写入口

`study_status` / `study_overview` 只读；写只有 `POST /mutate`（外加几个业务专用 POST）。
之所以不给模型「随便改数据」的工具：模型改错了没人看得见，而面板写错至少有一条 `409` 挡在前面。

### 5. 面板不用 iframe、不引宿主客户端包

`client.js` 直接渲染宿主组件（React 形态由宿主注入），样式只用 `--dsw-alias-*` 主题令牌。
好处是主题切换、深浅色、密度变化都自动跟随，不需要维护两套皮肤；代价是不能复用第三方 UI 库的样式。

### 6. 定时器不属于 `createApiHandler`

`createApiHandler` 在测试里被反复调用；如果它在构造时起一个 8 分钟的 interval，每个用例都会漏一个定时器。
所以心跳由 `index.js` 用 `ctx.effect(() => { const timer = setInterval(...); return () => clearInterval(timer); })` 起，
卸载时自然停；handler 上只留 `learn.checkNow()` 这类手动抓手给测试驱动。

### 7. `client.js` 与 `client.full.js` 两份

`client.full.js` 是可编辑的那一份，`client.js` 是随包发布的形态，二者必须**逐字一致**。
同步脚本 `tools/sync-client-full.mjs` 默认方向是 `client.js → client.full.js`——
**默认方向会把你的编辑冲掉**，改完 `client.full.js` 要用 `--reverse`。

## 六、错误处理策略

| 场景 | 选择 | 为什么 |
|---|---|---|
| 状态性失败（未连接、未就绪、未启用） | `200 + ok:false + reason` | 面板要显示状态灯；用 5xx 会和真故障混淆 |
| 缺少数据文件 | `/health` 报 `exists:false`；`/state` 单份报 `200 missing:true` | 「还没开始用」不是错误 |
| 数据文件损坏 | `409 + reason`，拒绝增量写 | 坏文件是事故，必须停下来让人修 |
| 上游失败（模型 / 平台） | `502` / `504` + 稳定 `reason` | 可重试的失败要和参数错误区分 |
| 未捕获异常 | `500 internal` + 记日志 | 不把堆栈回给浏览器 |

错误码是**契约**：`kebab-case`、稳定、不把异常文本拼进去。改错误码等同于改契约。

## 七、测试策略

- **`tests/*.test.js`，`node:test`，536 项**。不引测试框架，`npm test` 一条命令跑完。
- 边界分工：
  - `core.test.js` / `gpa.test.js`：纯函数与 GPA 计算；
  - `store.test.js`：原子写、冲突、备份轮转、损坏保护；
  - `http*.test.js`：状态码、守卫顺序、批量原子性、备份往返；
  - `host.test.js`：从源码反推「注册了哪些路由与工具」，防止加漏；
  - `client.test.js`：面板源码级检查（主题令牌、文案、不出现禁用 API）；
  - `lecture-*` / `learn-*`：平台与音频链路的解析与失败路径。
- **`npm run panel:smoke`**：不启动宿主，用真实数据把面板渲一遍，专抓白屏、`undefined`、`NaN`、`[object Object]`。
- `npm run verify:installed`：把「已装进 profile 的那份产物」加载起来跑契约断言——验证的是**装机结果**而不是源码。

## 八、已知的简化

- 知识点 `edges[]` 第一版留空（结构留好，由会话织网补）。
- 成绩条目没有稳定 id，因此只能 create 不能 update/delete（`normalizeGrade` 不写 id）。
- `/learn/sync` 写失败统一回 `409`，而 `/mutate` 区分 `409`（冲突）与 `422`（存储失败）——历史遗留，未统一。
- 讲解缓存不会自动清理，节点消失后只标 `stale`。
- 不做多端互斥：两个宿主指向同一 `dataDir` 时靠冲突检测挡，挡不住「人为忽略提示」。
