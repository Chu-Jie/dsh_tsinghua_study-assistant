### 排课字符串里有一处要注意

首页给出的排课文本形如「第1-16周星期一第1节，六教6A415」。其中「第N节」是**每次课的第一节**，

实验课则显示「第1-16周星期 第0节，」——**没有星期和节次**，这印证了插件里
`物理实验B(1)`／`数字电子技术实验` 需要人工补录节次（当初就是从课表截图补的）。

**另外**：首页显示的这些排课与插件 `课程.json` 目前记的节次**有出入**（网络学堂给的是「第N节」，
插件里是「第N-M节」区间）。这属于待核对项，不改也能用。

### 学生端作业列表接口（**已确认**，但请求形状比一开始以为的复杂）

第一次猜测的接口名全错。真正的接口是在学生端作业页的 `<script>` 里直接读出来的 —— 那个页面用
jQuery DataTables 的 `MyApp.createServerTable` 拉数据，三个页签对应三个接口：

| 页签 | 接口 | 说明 |
|---|---|---|
| 未提交 | `POST /b/wlxt/kczy/zy/student/zyListWj?_csrf=<token>` | **导入 DDL 主要靠它** |
| 已提交未批改 | `POST /b/wlxt/kczy/zy/student/zyListYjwg?_csrf=<token>` | 也带截止时间，用于补全历史 |
| 已批改 | `POST /b/wlxt/kczy/zy/student/zyListYpg?_csrf=<token>` | 含成绩字段 |

课堂号**不是**查询串参数，而是放在表单体里 —— 这一条最初写错了（写成 `GET ...?wlkcid=`），
真机上全部 HTTP 400。纠正过程与证据见下面两小节。

### 请求形状：POST + `aoData` + `_csrf`（**踩坑踩出来的**）

一开始按 `GET ?wlkcid=...` 实现，真机三个接口**全部 HTTP 400**。没有再猜，而是去读平台自己的三处实现：

1. `myApp.js` 的 `createServerTable(s)` 尾部：`dataTableReqUrl = handleUrlWithCsrf(s.url);` 然后才建表 ——
   说明 URL 会被动过手脚。
2. `dataTablePlugin.js` 的 `fnServerData`（真正的发送点）：
   ```js
   $.ajax({ "type" : 'POST', "url" : sSource, "dataType" : "json",
            "data" : { aoData : JSON.stringify(aoData) },
            "success" : function (data) { if (data.result == 'success') fnCallback(data.object); ... } })
   ```
   同一函数里 `defaultSearchCondition` 是被 **push 进 `aoData`** 的，不是放进查询串。
3. jQuery 层的 `ajaxSend`：`settings.url += separator + '_csrf=' + encodeURIComponent(getCookie("XSRF-TOKEN"))`。

然后用 `tools/probe-learn-zy-shape.mjs` 把六种候选形状各实测一次：

| 形状 | 结果 |
|---|---|
| `GET ?wlkcid=...` | **HTTP 400**（Tomcat 错误页） |
| `GET ?wlkcid=...&_csrf=...` | **HTTP 400** —— GET 本身就不对 |
| `POST ?_csrf=...`，body `aoData=[]` | **HTTP 200**，但 `aaData` **26 条且跨学期** |
| `POST ?_csrf=...`，body `aoData=[{name:'wlkcid',value:...}]` | **HTTP 200**，1 条，正确 |
| `POST ?_csrf=...`，body 完整 DataTables 骨架 | **HTTP 200**，与上一条相同 |

**三条缺一不可**：① 必须 **POST**；② `Content-Type: application/x-www-form-urlencoded`，
body 是单个参数 `aoData=<JSON.stringify([{name,value},…])>`；③ URL 上带 `?_csrf=<urlencoded token>`。
DataTables 的分页骨架字段**不是必需的**（仍然带上，因为那是浏览器里真实发出的形状 —— 少猜一点就
少一次「某天服务端加了校验、我们突然全空」的事故）。

> ⚠ **`wlkcid` 必须放进 `aoData`**。空的 `aoData` 同样返回 200，但那是不分学期的**全部**作业，
> 会静默导入一堆陈年数据。这是最危险的一类失败：不报错，只是数据全错。

**响应信封**：`{result:"success", msg:…, object:{iTotalRecords, iTotalDisplayRecords, aaData:[…]}}`，
**行在 `object.aaData`**（不是 `aaData` 顶层）。

### 课程列表接口：首页 HTML 里没有，是**两段式**

原计划从学生端首页 HTML 里正则扫课堂号与课程名。**这条路真机走不通**：首页里的课程列表是
JS 模板 —— `<input class="wlkcid" type="hidden" value="{{value.kcid}}">` ——
`wlkcid=2026-…` 形式出现 **0 次**，所以永远扫出 0 门课（`--list` 当时显示「我的课堂（0 门）」）。

真正的接口写在 `/res/js/wlxt/kc/kc/student/courseList.js` 里：

```js
$.getJSON("/b/wlxt/kc/v_wlkc_xs_xktjb_coassb/queryxnxq", function(data){ ... })   // 学期串数组
initCourse = function(id, semesterId){
  $.get("/b/wlxt/kc/v_wlkc_xs_xkb_kcb_extend/student/loadCourseBySemesterId/"+semesterId+"/"+locale+"?timestamp="+getTimestamp, ...)
```

- `queryxnxq` 的真实响应是 `[null,"2026-2027-1","2025-2026-3","2025-2026-2","2025-2026-1"]` ——
  **首个元素是 null**，不是对象数组；服务端**由新到旧**返回，所以默认取第一个。
- 课程元素里：**`wlkcid` 是课堂号、`kcm` 是课程名、`xnxq` 是学期、`jsh` 是教师号**，
  **`xf`（学分）字段存在但实测返回 null** —— 所以学分仍然只能由用户自己填。
- 学期串按 `-` 切：`list[2] == "1" → 秋季, "2" → 春季, "3" → 夏季`。

列定义就是字段清单（`head.columnMap`）。作业行的字段：

| 字段 | 含义 | 备注 |
|---|---|---|
| `bt` | 作业标题 | |
| `zyid` | 作业 ID | 课程维度 |
| `xszyid` | **学生作业 ID** | **去重键用它**（页面的 `getId` 就是返回它） |
| `wlkcid` | 课堂号 | |
| `mxdxmc` | 发布对象 | |
| `zywcfs` | 完成方式 | `2` = 组，否则个人 |

| **`jzsj`** / **`jzsjStr`** | **截止日期（GMT+8）** | 数值是**毫秒时间戳**；UI 显示用 `jzsjStr` |
| `bjjzsj` / `bjjzsjStr` | **补交截止时间** | 非空时列表会多显示一个「补交」行 |

| `scsjStr` / `jsm` / `pysjStr` / `cj` / `djzcj` | 提交日期 / 批阅老师 / 批阅日期 / 成绩 / 等第制成绩 | 仅「已批改」有 |

**两个决定性细节**：

1. **`jzsj` 是毫秒时间戳**（真机实测 `jzsj:1791813600000` ↔ `jzsjStr:"2026-10-12 22:00"`，按 +08:00 对齐）。
   页面里的判断是 `var time = row.jzsj - beginTime2.getTime();` 再 `Math.floor(time / 86400000)` 算天数。
   虽然有现成的 `jzsjStr`，**插件仍以毫秒 `jzsj` 为主**：字符串要再解析一次格式，
   而毫秒可以直接和 `Date.now()` 比，也免掉「平台换格式」的风险。
2. **截止时间口径有两个**：`jzsj`（正常截止）与 `bjjzsj`（补交截止）。
   页面判断「还能不能交」用的是**两个都没过**（`time<=0 && time1<=0` 才算彻底过期）。
   插件以 `jzsj` 为主截止、`bjjzsj` 只作为 `grace` 宽限提示，**不把补交期当主截止** ——
   否则提醒会晚一整周。

### 认证：已定论（`/f/**` 只要 Cookie，`/b/**` 缺 XSRF 头就 403）

这里曾经有个看似矛盾的现象：页面里拉数据的 jQuery 是**标准 `$.ajax`，没设任何自定义头**，
暗示 `/b/**` 只要 Cookie；但未登录探测显示「不带 `X-XSRF-TOKEN` → 403」。

**真机跑通后定论：两边说的都对，只是缺的东西不一样。**

| 路径 | 实测 `authUsed` | 结论 |
|---|---|---|
| `/f/wlxt/index/course/student/`（页面） | `cookie` | 只要有会话就行 |
| `/b/wlxt/kc/…/queryxnxq` | `cookie+xsrf` | 纯 Cookie 被 403，补头才 200 |
| `/b/wlxt/kc/…/loadCourseBySemesterId` | `cookie+xsrf` | 同上 |
| `/b/wlxt/kczy/zy/student/zyListWj` | `cookie+xsrf` | 同上 |

「没设自定义头」是**看漏了**：平台在 jQuery 的 `ajaxSend` 钩子里统一补 `_csrf` 查询参数
（见上面「请求形状」），所以业务代码里确实看不到任何 CSRF 相关的东西。

**对用户的要求因此是明确的：粘贴时必须带上 `XSRF-TOKEN`**（整条
`JSESSIONID=...; XSRF-TOKEN=...`）。`learnRequest` 仍然保留了「先只发 Cookie，403 且有 XSRF cookie
就补头重试一次」的自动升级（`authUsed: 'cookie' | 'cookie+xsrf'`），但那只是兜底 ——
课程列表与作业列表全在 `/b/**`，少一个字段就什么都拿不到，不该依赖重试。

## 〇之二、已实现（2026-09-30）

同步功能已写进插件本体，不再是探针。**数据改动不需要重装插件**——宿主每次请求实时读文件，
只有改 `client.js` / `lib/*.js` 才需要重装 + 重启 DSH。

### 服务端（`lib/learn.js` + `lib/api.js`）

`lib/learn.js` 是零依赖的纯函数 + `fetch` 层：**不碰文件系统**（任务 id 的生成器由调用方注入），
所以解析逻辑可以被零依赖测试完整覆盖。`lib/api.js` 在其上加了六个路由（1 个 GET + 5 个 POST）：

| 方法 | 路由 | 作用 |
|---|---|---|
| GET | `/api/study-assistant/learn/status` | 连接状态。**绝不回传 Cookie 本身**，只回 `{connected, updatedAt, semesterId, manualCount, courses, counts:{courses,matched}}` |
| POST | `/api/study-assistant/learn/connect` | 存 Cookie 并验活，返回课堂号与本地课程的匹配结果 |
| POST | `/api/study-assistant/learn/fetch` | **预览**：算出会导入哪些作业，不落盘 |
| POST | `/api/study-assistant/learn/sync` | **导入**：一次读、一次写，落盘到 `任务.json` |
| POST | `/api/study-assistant/learn/semester` | **换学期**：用已存的凭证重拉课程并重做匹配。界面拿不到 Cookie，所以这件事只能服务端做 |
| POST | `/api/study-assistant/learn/disconnect` | 删掉凭证文件。**不动 `任务.json`**：已导入的任务是用户数据 |

五个 POST 都走和其它写接口同一套闸门：要求 `Content-Type: application/json` + 自定义头
`x-study-request: 1`，且拒绝跨站请求。

**这六条路由能被浏览器访问到，还取决于宿主那一侧的注册**（2026-09-30 真机 404 的根因）：
`index.js` 必须写 `ctx.webServer.register({ kind: 'prefix', path: '/api/study-assistant', handler })`。
宿主 `dsh-host-webserver` 的 exact 路由是**精确匹配**，子路径根本进不来；只注册成 exact 的话，
`/learn/*` 在真机上返回 **404**，而不带令牌探测时返回的 **401** 与「一个根本不存在的路径」
返回的完全一样（拿 `/api/study-assistant/bogus-zzz` 对照即可复现），
很容易被误判成「路由存在、只是要鉴权」。详见 `README.md` 第九节第 9 条。

### 凭据怎么存（重要）

Cookie 存在数据目录下的 **`网络学堂.json`**（先写 `.tmp` 再 `rename`，避免断电留半截 JSON）。
它**刻意不在 `DOC_FILES` 白名单里**，因为它是凭据而不是学习数据：

- 不出现在 `/state` 的返回里，也不会被 `/reset-doc` 碰到（对 `learn` / `网络学堂` / `credential`
  这三个 key 都返回 400）；
- `/learn/status` 只回「连没连上」和课堂名，不回 Cookie 值；
- 断开就是把这个文件删掉。

测试里专门放了一份带 `SECRET-VALUE` 的假配置，断言 `/state` 正文里既没有这个值也没有「网络学堂」
字样——**凭据隔离是被测试锁住的，不是靠自觉**。

### 匹配与去重

- **匹配**顺序：手动映射 → 归一化后完全相同 → 别名精确 → 唯一前缀。
  命中多个前缀时返回 `ambiguous` 而**不猜**——挂错课比暂时不挂更难发现。
  「归一化」包含**全角/半角括号与标点**：本地写「英语阅读写作(A)」、学堂写「英语阅读写作（A）」，
  这是输入法差异，不该让用户去加别名，`normalizeWideChars` 直接消化掉。
- **学期是记住的，而且能换**：`网络学堂.json` 里存 `semesterId` 与 `semesters`，
  连一次之后不再每次重问；DDL 页签的按钮行里，有多个学期时会出现一个下拉框，
  换学期走 `POST /learn/semester`（服务端用自己的 Cookie 重拉课程并**重做匹配**——
  同一门课在不同学期有不同的课堂号，不重匹配就会把新课挂到旧课上）。
  跨学期后不该悄悄把新课当旧课的补充，所以这个下拉框是必需的，不是装饰。
- **别名**：课程页可给每门课编辑别名（逗号/顿号/分号分隔，**空格不是分隔符**）。
  这是「数电」「数电实验」这类简称的唯一解法：学堂里叫「数字电子技术基础」，本地叫「数电」，
  没有别名就永远对不上（注意「数字电子技术实验」是另一门课，别名里别混）。
- **去重**用一个写在任务 `note` 里的记号 `[learn:<key>]`，`key` 优先 `xszyid`。
  不新增文档字段，因为 `任务.json` 的形状已被测试锁住；`note` 是自由文本，用户删掉记号即等于解绑。
- **提交状态照抄平台**：`LEARN_LISTS` 里的 `open: true/false` 就是判据 ——
  来自「已提交未批改 / 已批改」两张表的行直接落 `done`，只有「未提交」表的行才是 `todo`。
  这一条曾经漏掉（`open` 从来没有读者，而 `toTaskItem` 把状态写死 `todo`），
  后果是一堆早就交了的作业挂在「未完成」里；更麻烦的是去重按远端记号跳过，
  这些错条目**不会自我修正**。现在同步时还会**补标**历史数据：本地 `todo`、平台已交的
  就地升为 `done`，返回里报 `completed`（界面提示「N 条早就交过的补标为完成」）。
  **只单向升级** —— 平台没交不代表用户没做（线下交、课堂交、老师还没登记都可能）。
  **可核对的不变量**：同步后「未完成」的任务条数应等于首页各课堂未提交数之和（本学期是 4）。
- **截止时间**以 `jzsj` 为主截止，`bjjzsj` 只作为补交宽限信息附在后面。若反过来，提醒会晚一周。
- **过期的不默认勾选**，但仍会列出来——网络学堂的历史里常有已经错过、但用户还想补的作业。

### 界面

DDL 页签**最顶部**新增「网络学堂同步」卡片。交互刻意是**两步**：

1. 「预览要导入的作业」——列出将要导入的条目（截止时间 / 标题 / 对应科目 / 是否已过期），
   并单独列出**没匹配上课程**的条目与可操作建议；
2. 「导入 N 条」——确认后才写盘。

**为什么不做成一步**：远端作业名和本地课程对不上是很常见的情况，直接导入会让用户在一堆
`courseId` 为空的任务里自己找原因。预览把「会导入什么、哪门课没匹配上」摆在按钮前面。

个别接口抽风时只在预览里显示`N 个接口没取到数据`的警告，**不整批失败**——网络学堂经常个别
课堂/接口超时，不能因此丢掉其余已经取到的作业。

导入完成后的提示会报三件事：`已导入 N 条`、`M 条早就交过的补标为完成`、`跳过 K 条已导入过的`。
中间那一项是**修历史数据**用的：上一次用旧规则（一律 `todo`）导进来的已交作业，会在下一次同步时
被就地升级为「已完成」，不需要用户手点。

## 一、实测结论（都是本机实跑，不是推测）

在 DSH 沙箱里能正常访问外网，`learn.tsinghua.edu.cn` 可达：

| 探测项 | 结果 |
|---|---|
| `GET https://learn.tsinghua.edu.cn/` | 302 → `/f/redirectByStuOrTeacher` → `/f/login` |
| 登录页 `/f/login` | 200，表单字段 `i_user` / `i_pass` / `atOnce` |
| `GET /b/wlxt/**`（不带 CSRF 头） | **403**（一片中文错误页，标题「网络学堂」） |
| `GET /b/wlxt/**`（带 `X-XSRF-TOKEN`） | **200 + JSON** ✓ |
| 沙箱能否发外网请求 | **能**（不是登录用户也能拿到公开数据） |

### 关键发现 1：CSRF 只需要 cookie 里的 XSRF-TOKEN

访问任意页面会拿到两个 cookie：`XSRF-TOKEN` 与 `JSESSIONID`。之后每个 `/b/**` 请求都要带上：

```
Cookie: JSESSIONID=...; XSRF-TOKEN=...
X-XSRF-TOKEN: <XSRF-TOKEN 的值>
```

实测 `GET /b/wlxt/xt/wlxt_tsk/querytsk` 加了 `X-XSRF-TOKEN` 立刻从 403 变 200：

```json
{"message":"success","resultList":[{"kcid":"1","kcurl":"...","kctp1":"2003980816_sys_17", ...}]}
```

（这个接口本身不需要登录，返回的是公开课程信息。）

### 关键发现 2：登录方式有两种，第二种对插件友好得多

`/res/js/common/login.js` 里写得很清楚：

1. **账号密码**：`$.post(baseUrl + '/b/ajaxLogin', param)`，表单字段 `i_user` / `i_pass`。
   密码以明文形式 POST（页面里没有前端加密逻辑）。
2. **清华统一身份认证（CAS / SSO）**：
   ```js
   https://id.tsinghua.edu.cn/do/off/ui/auth/login/form/bb5df85216504820be7bba2b0ae1535b/0
   ```
   走的是标准 CAS 跳转，登录成功后回跳并建立 `JSESSIONID` 会话。

### 关键发现 3：接口是规整的 JSON REST

命名规则一眼就能推出来：

```
/b/wlxt/<模块>/<实体>/<角色>/<动作>
```

已经看到的模块（`common.js`、`login.js`、登录页里挖出来的）：

| 路径 | 含义 |
|---|---|
| `/b/wlxt/kczy/xszy/*` | 课程作业（学生作业） |
| `/b/wlxt/kczy/zy/*` | 作业 |
| `/b/wlxt/kj/wlkc_kjxxb/*` | 课件信息 |
| `/b/wlxt/kcgg/wlkc_ggb/*` | 课程公告 |
| `/b/wlxt/bbs/bbs_tltb/*` | 讨论区 |
| `/b/wlxt/jxbj/wlkc_jxbjb/*` | 教学班级 |
| `/b/wlxt/kc/v_kczyxxb_search/pageList` | 课程作业查询（分页） |
| `/b/wlxt/xt/wlxt_tsk/querytsk` | 公开课程列表（无需登录） |

注意 URL 里的 **`teacher`** 段是教师视角（`common.js` 是教师端脚本）。
学生视角的对应路径（多半是 `student` 或 `xs`）**必须登录后才能探测**，目前还没确认。

## 二、可行性判断

| 维度 | 判断 |
|---|---|
| 沙箱能发外网请求 | ✅ 已实测 |
| 接口返回结构化 JSON | ✅ 不是要爬 HTML |
| 有 CSRF 头要求 | ⚠️ 可解决，固定加两个头即可 |
| 需要登录 | ⚠️ **唯一的硬门槛** |
| 登录方式 | 账号密码（明文 POST）或 CAS 单点登录 |
| 需要零依赖 | ✅ Node 24 自带 `fetch`，解析 JSON 不需要库 |

**结论：能做，但认证是设计问题而不是技术问题。**

## 三、三种认证方案的取舍

| 方案 | 用户操作 | 风险 | 评价 |
|---|---|---|---|
| **A. 会话 cookie 粘贴** | 浏览器登录网络学堂 → F12 复制 `JSESSIONID` → 粘进插件 | 无密码落盘；cookie 有效期短（会话级，通常几十分钟到几小时） | **推荐**。最安全，缺点是过期要重粘 |
| **B. 存账号密码自动登录** | 填一次账号密码，插件调 `/b/ajaxLogin` | **明文密码存在本地 JSON 里**；插件代码出 bug 可能把密码写进日志 | 不推荐 |
| **C. WebView / 内嵌浏览器走 CAS** | 在插件里登录一次 | 需要在插件里开一个浏览器视图，实现复杂度高；DSH 客户端插件目前没有现成的 webview 能力 | 长期方案，代价大 |

### 我建议的做法：A + 「刷新按钮」

1. 设置页加一个「网络学堂」小节：粘贴 `JSESSIONID`（或整条 Cookie 头）。
2. 插件只把 cookie 存在 `<dataDir>/网络学堂.json`，且**不写进备份、不进日志**。
3. 每次同步前先打一个轻量接口验活；失效就提示「会话已过期，请重新粘贴」。
4. 同步下来的是 JSON → 映射成 `任务.json` 里的任务（去重靠 `kczyid` 之类的稳定 id）。
