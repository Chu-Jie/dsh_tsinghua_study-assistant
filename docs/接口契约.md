# 接口契约

本文是 `/api/study-assistant/*` 的**对外契约**：传输规则、路由表、错误码、数据模型，以及「要加一条接口时必须守的规矩」。

> 数据文件格式版本 `DOC_VERSION = 1`。改下表的字段形状、枚举、id 规则、错误码语义都算**破坏性变更**，
> 需要同时递增 `DOC_VERSION` 并写迁移。

---

## 一、传输层

| 项 | 约定 |
|---|---|
| 前缀 | `/api/study-assistant`（宿主侧以 `kind: 'prefix'` 注册，先精确匹配 handlers、再按前缀落到本插件） |
| 监听 | **不另起端口**，复用宿主自己的 Web 服务器（回环地址） |
| 方法 | 只接受 `GET` / `POST`；其它方法回 `405`，带 `Allow: GET, POST`，**无响应体** |
| 编码 | 请求与响应都是 JSON（`Content-Type: application/json; charset=utf-8`）；音频/图片/HTML 例外，见对应路由 |
| 响应头 | 所有响应带 `Cache-Control: no-store`；图片路由是唯一例外（`public, max-age=86400, immutable`） |
| Cookie | **从不写 `Set-Cookie`**。鉴权不靠 Cookie，靠宿主自身的同源约束 |
| 成功 | `200` + `{ ok: true, … }`（`/health` 在数据不健康时回 `503` + `ok:false`） |
| 失败 | `{ ok: false, error: '<kebab-case-reason>' }`，必要时附 `key` / `path` / `detail` |
| 未知路由 | `404 { ok: false, error: 'unknown-route', path }` |
| 未捕获异常 | `500 { ok: false, error: 'internal' }`（同时写一条 error 日志；已发头则直接结束响应） |

`error` 一律**机器可读的 kebab-case 标识**，不把异常文本、堆栈、路径拼进错误码；给人看的说明放 `detail`。

---

## 二、写请求的三道闸

所有 `POST` 在解析请求体**之前**过 `writePreflight`，顺序固定：

| # | 检查 | 失败响应 |
|---|---|---|
| 0 | 来源：`Sec-Fetch-Site: cross-site` 直接拒 | `403 { error: 'cross-site-rejected' }` |
| 1 | `Content-Type` 必须是 `application/json`（或 `+json`） | `415 { error: 'need-json-content-type' }` |
| 2 | 必须带自定义头 `X-Study-Request: 1` | `403 { error: 'need-request-header' }` |

两点：

- 自定义头的目的是让**跨站表单**构造不出合法写请求（表单带不了自定义头，带头的 fetch 会触发预检，而预检过不了同源约束）。
- `skipContentType: true` 只有两处：`POST /reset-doc`（危险操作，只有空体或简单体）与 `POST /lecture/chunk`（二进制 WAV）。

**GET 不需要任何头**——只读路由不设闸，靠「不返回凭据」来兜底（`/learn/status` 与 `/state` 都不含 Cookie）。

## 三、请求体解析与限额

| 项 | 值 | 说明 |
|---|---|---|
| 通用体积上限 | `MAX_BODY_BYTES = 1 MiB` | 所有 JSON 写请求 |
| 文本/JSON 超限 | `413 { error: 'too-large' }` | 超限后仍把请求体排空，否则客户端会看到连接被重置而不是 413 |
| 解析失败 | `400 { error: 'read-error' }` / `400 { error: 'bad-json' }` | 分开报，便于区分网络中断与 JSON 语法错误 |
| 二进制读取 | `readBody(req, { binary: true })` | **不做 UTF-8 解码**；WAV 若被当字符串读会逐字节改坏 |
| 音频上限 | `LECTURE_MAX_BODY_BYTES = 44 + 120×32000 + 4096 = 3,844,140` 字节 | `44` 是规范 WAV 头，`120 s` 是单片上限，`4096` 留给元数据。**不能复用 1 MiB**：16 kHz 单声道 PCM16 每秒 32,000 字节，60 秒就 1.92 MB |

## 四、路由总表

**共 44 条**：`GET` 21（20 条精确 + 1 条通配 `/lecture/<name>.js`）、`POST` 23。
分派用最朴素的 `if (rest === '…')` 链——GET 链在前，POST 链在后，都不建路由表对象。

### 4.1 核心

| 方法 | 路径 | 参数 | 返回 |
|---|---|---|---|
| GET | `/health` | — | `200 { ok, healthy, dataDir, docs: {<key>: {exists, bytes, ok, reason?}} }`；不健康回 `503` |
| GET | `/state` | `?doc=<key>` 可选 | 单份：`200 { ok, key, doc, hash }`；文件不存在：`200 { ok: true, doc: null, hash: null, missing: true }`（**不是 404**）；损坏：`409 { error: <reason>, key, hash }` |
| GET | `/state`（不带 `doc`） | — | `200 { ok: true, docs, problems, hashes, files }`——`hashes[key]` 是每份文档的 sha256，客户端拿它做乐观并发 |
| GET | `/overview` | `?now=ISO` 可选 | `200 { ok, overview, counts: {courses, activeTasks, terms}, term, problems }` |
| POST | `/mutate` | 见 4.2 | `200 { ok, key, hash, count, updated? }` |
| POST | `/reset-doc` | `{ doc }` | 把一份文档重置为空结构前先备份；`unknown-doc` 时**不带** `allowed` |

> `/state` 不带 `doc` 时 `ok` 恒为 `true`——per-document 的损坏由 `problems[]` / `doc: null` 表达。
> 这里踩过坑：曾写成 `{ ok: true, ...all }`，`readAll()` 自带的 `ok:false` 把外层覆盖了，
> 结果一份文档损坏就让面板对四份完好数据全部报「读取失败」。

### 4.2 `POST /mutate`（唯一的通用写入口）

```json
{ "doc": "tasks", "action": "create | update | delete", "item": {…}, "id": "t_xxx", "expectedHash": "sha256:…" }
```

批量更新（面板一次勾一片）：

```json
{ "doc": "knowledgeNetwork", "action": "update", "expectedHash": "…",
  "items": [ { "id": "k_xxx", "item": { "mastery": 2 } }, … ] }
```

- `items` 上限 **500**，超了直接 `400 too-many-items`——**不静默截断**（截断会让调用方以为全改了）。
- 批量语义是**全成或全不成**：任一条 id 不存在或不合法，整体不写盘。
- `expectedHash` 省略时用服务端本次刚读到的 hash——仍能挡住「读之后被别人改过」。
- 未知 `doc` / `action` / 非法 id / 字段非法 → `400`；id 找不到 → `404 not-found`；并发冲突 → `409 conflict`；存储失败 → `422`。
- `knowledgeOutline` 与 `knowledgeAnalysis` 在 `DOC_KEYS` 里但**不给 `DOC_ROUTES`**，走 `/mutate` 会回 `400 use-dedicated-route`（它们由专用工具整份落盘）。
- 删除课程前查引用：仍有任务或成绩引用它 → `409 course-in-use` + `references: {tasks, grades}`。

### 4.3 备份

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/backup/export` | `200 { ok, count, skipped, bundle }`。缺/坏的文档**不进包**，记进 `skipped[{key, reason}]` |
| POST | `/backup/restore` | 接受 `bundle` 或 `{ bundle }`；先整包验校验和+逐份 `validateDoc`，全过才写。回 `200`（至少写进一份）或 `422`；逐份报 `restored[] / failed[]`，**不事务、不回滚** |

包形状（`BUNDLE_FORMAT = 'study-assistant.bundle'`，`BUNDLE_VERSION = 1`）：

```json
{ "format": "study-assistant.bundle", "version": 1, "exportedAt": "…",
  "docs": { "<key>": {…} }, "hashes": { "<key>": "sha256:…" },
  "checksum": "sha256:…", "app": { "name": "dsh-study-assistant", "dataDir": "…" } }
```

`checksum` 对 `docs` 的**键排序规范 JSON** 求值——手写工具重排键序不会让校验和变。

恢复失败的错误码用于定位**哪一份**不合法：`checksum-mismatch`（附 `expected` / `actual`）、`invalid-doc`（附 `key` / `detail`）、`bad-format`、`bad-version`。

### 4.4 提交件归档

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/deliverables` | `200 { ok, enabled, reason, root, studentName, studentId, findings[] }` |
| POST | `/deliverables/archive` | `{ items?: [{taskId, file}] }`；省略 `items` 时归档本次扫描里全部 `ready` 命中 |

- `findings[]` 每条 `{ file, basename, courseId?, taskId?, status, candidates? }`；
  `status` 取值 `ready`（唯一命中）/ `ambiguous`（多个候选，只提示不归档）/ 其它表示「不构成归档依据」（缺姓名/学号、课程对不上等）。
- **服务端重新扫描后校验白名单**：客户端不能凭一个 `taskId` 就要求归档——只接受本次扫描里 `ready` 的命中或 `ambiguous` 列出的候选，
  否则进 `skipped[{taskId, file, reason:'not-a-candidate'}]`。这是「文件放进去才归档」这条约定的落地点。
- 其它 `skipped` 原因：`task-not-found`、`already-done`（幂等：已归档的不重复写）、字段校验失败。
- 单次上限 200 条；`items` 为空且无 `ready` 命中时不写盘，回 `200 { archived: [], skipped: [] }`。
- `enabled:false`（`studentId` 为空）时两张表都回 `200 { ok: true, enabled: false, reason }`，**不是错误**。

### 4.5 资料正文与插图

| 方法 | 路径 | 参数 | 说明 |
|---|---|---|---|
| GET | `/materials/text` | `path` 必填、`page` 可选 | 只认《资料索引.json》登记过的 `path`；按 `tier-gemini-pageNN.md` → `gemini-pageNN.md` → `pageNNNN.md` 挑 OCR 产物，一次一页 |
| GET | `/materials/image` | `path` 必填 | 只认 `<dataDir>/图片/_index.json` 里登记的图；`<= 8 MiB`；扩展名走白名单映射 |

共同错误码：`400 missing-path`、`403 escape`（`..` 越界或解析后跑出工作区根）、`404 not-indexed` / `missing` / `page-missing` / `no-index`（无索引文件）、
`415 unsupported-type`（图扩展名不在白名单）、`413 too-large`（图超 8 MiB）。

图片成功响应额外带 `X-Study-Image: <encodeURIComponent(caption)>`，`Cache-Control: public, max-age=86400, immutable`
——图按「内容命名 + 索引登记」发布，同名文件不原地改，改了就是新文件。

### 4.6 作业流

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/homework/spawn` | `{ taskId }`；校验任务与课程后**建一个新会话**并投固定指令，返回 `{ sessionId, taskId, course }` |

错误：`400 missing-task` / `bad-id`、`404 unknown-task`、`409 course-not-found`、`503 sessions-unavailable`（宿主没提供会话接口）、`502`（建会话失败，带 `detail`）。
它**只负责开工**：取字、分题、生成、交付都由会话里的 agent 做。

### 4.7 网络学堂（`/learn/*`，13 条）

| 方法 | 路径 | 说明 |

| GET | `/learn/status` | 连没连上、缓存了哪几门课、最近一次检查时间；**不含 Cookie** |
| GET | `/learn/session` | 会话自愈状态：票是否还有效、后台浏览器在不在跑 |
| GET | `/learn/detail?taskId=` | 服务端去平台拉「查看作业」页并解析成结构化字段，写 `任务详情.json` 缓存（TTL 3 分钟） |
| GET | `/learn/updates` | 比对「本地任务 vs 平台」的截止时间差异，只读 |
| POST | `/learn/connect` | `{ cookie, semesterId? }`：验活 → 存凭证 → 匹配课程。**Cookie 有效就存**，哪怕一门课都没匹配上 |
| POST | `/learn/fetch` | 预览：会导入什么、哪门课没匹配上；**不落盘** |
| POST | `/learn/sync` | 真正导入（去重记号 `[learn:<key>]` 写在任务 `note` 里；平台已提交/已批改的行单向升级为 `done`） |
| POST | `/learn/apply-updates` | `{ items }`：只改这些任务的 `due`，一次读一次写 |

| POST | `/learn/login-window` | 弹一个可见的登录窗口去收 Cookie；永远 `200` |
| POST | `/learn/browser-stop` | 关掉后台浏览器（只动浏览器，不碰数据） |

因为面板要显示状态而不是报错；「要人工登录」是**冷却 20 分钟**的封条，不是故障。

### 4.8 听课（`/lecture/*`，14 条）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/lecture/health` | 功能就绪度；**永远 200**，用 `ok:false` 表达「没就绪」 |
| GET | `/lecture/state` `/lecture/sessions` `/lecture/report` | 当前会话状态、历史会话、这次课的听课报告 |
| GET | `/lecture/panel` | 听课面板 HTML；`/lecture/import` 是导入页 HTML |
| GET | `/lecture/<name>.js` | **唯一通配路由**：下发面板自己 import 的 ES 模块；名字必须过 `clientModulePath` 白名单（挡 `../../`） |
| GET | `/lecture/recording/list` `/lecture/recording/file` | 录音笔音频：列表 + 按偏移读字节（页面自己解码） |
| POST | `/lecture/session/start` `/session/stop` `/feed` | 会话开始/结束、喂文本（读屏 OCR 或手动粘贴） |
| POST | `/lecture/alert/ack` | 点名提醒的确认/忽略（同一提醒只提醒一次） |
| POST | `/lecture/chunk` | 二进制 WAV（`skipContentType`）；单片 `0.3–120` 秒 |

音频只认规范 WAV：**16 kHz / 单声道 / PCM16**——DSH 的 `speechToText` 会逐字段校验，
不符合直接抛 `Audio must be a canonical 16 kHz mono PCM16 WAV recording`。
所以 `/lecture/chunk` 的失败码是 `400 bad-audio`（格式不对）与 `413 too-large`（超限）分开报。

### 4.9 知识点（5 条）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/knowledge/explain?node=&style=` | 读讲解缓存：带 `node` 返回该节点的缓存（可带 `style`），不带 `node` 列出全部已生成 |
| POST | `/knowledge/explain` | `{ node, style, force? }`：现场生成一档，写 `讲解缓存/<id>-<档>.md`；`force:true` 才跳过缓存 |
| POST | `/knowledge/chat` | `{ node, messages[] }`：内嵌多轮问答，带整段对话、**不落盘** |

## 五、状态码与错误码语义

| 码 | 含义 | 典型 `error` |
|---|---|---|
| 200 | 成功；**状态性失败也用 200 + `ok:false`**（`/learn/renew`、`/lecture/health`、`/deliverables` 未启用） | — |
| 400 | 参数缺失/非法、JSON 坏、id 不合法、批量超限 | `missing-path` `bad-payload` `bad-id` `bad-json` `too-many-items` `use-dedicated-route` |
| 401 | 上游凭证失效（平台返回登录页） | `cookie-invalid` |
| 403 | 缺自定义头、跨站、路径越界 | `need-request-header` `cross-site-rejected` `escape` |
| 404 | 路由不存在、记录不存在、页不存在 | `unknown-route` `not-found` `missing` `page-missing` `not-indexed` |
| 405 | 方法不是 GET/POST（无体，带 `Allow`） | — |
| 409 | 并发冲突、文件损坏、仍被引用 | `conflict` `bad-field:*` `bad-version:*` `course-in-use` |
| 413 | 请求体/图超限 | `too-large` |
| 415 | Content-Type 不对、图扩展名不支持 | `need-json-content-type` `unsupported-type` |
| 422 | 存储写入失败（校验不过/磁盘问题） | `refuse-invalid:*` `refuse-corrupt-on-disk:*` |
| 500 | 未捕获异常 | `internal` |
| 502 / 504 | 上游（模型 / 平台）失败或超时 | `llm-*` `upstream-*` |
| 503 | 依赖未就绪 | `sessions-unavailable` `llm-unavailable` |

**「功能未就绪」不要用 5xx**：听课面板未就绪、网络学堂未连接这类状态，一律 `200 + ok:false`，
否则面板的状态灯会和真故障混在一起。

## 六、数据模型

`DOC_VERSION = 1`；每份文档顶层都有 `version` 与 `updatedAt`。`validateDoc` 只校验**顶层必需字段的类型 + version**，
不做逐字段深校验（深校验由各 `normalize*` 负责）。

| key | 文件 | 顶层必需字段 | 条目主要字段 |
|---|---|---|---|
| `term` | `学期.json` | `terms[]`、`currentId` | `id, name, startDate, endDate, totalWeeks, isCurrent` |
| `courses` | `课程.json` | `courses[]` | `id, name, aliases[], teacher, credits, type, sessions[{weekday,startPeriod,endPeriod,weeks,location}], note, createdAt` |
| `tasks` | `任务.json` | `tasks[]` | `id, title, courseId, kind, due, status, priority, estimateHours, progress, doneAt, note, createdAt` |
| `grades` | `成绩.json` | `courses[]`、`rules{}` | 课程 → `items[]`；`rules: {mode, formula}`；`targets[]` |
| `homework` | `作业.json` | `records[]` | `id, courseId, title, sourceFile, sourceHash, sourceKind, pageCount, draft, questions[], model, createdAt, updatedAt` |
| `materials` | `资料索引.json` | `files[]` | `path, courseId, kind, textLayer, ocr` |
| `questions` | `题目.json` | `questions[]` | `id, courseId, sourceFile, sourceHash, homeworkSeq, no, prompt, page, kind, knowledgeNames[], confidence` |
| `knowledgeCandidates` | `知识点候选.json` | `candidates[]` | `courseId, name, aliases[], chapter, evidence[]` |
| `knowledgeNetwork` | `知识点网络.json` | `nodes[]`、`edges[]` | 节点：`id, name, courseId, chapter, section, subsection?, aliases[], mastery, marked, reviewedAt, note, evidence[], createdAt` |
| `knowledgeOutline` | `知识点大纲.json` | `courses[]` | `sources[{courseId,book,pages[]}]`；课程 → `chapters[{no,title,page,sections[{no,title,page,subs[]}]}]` |
| `knowledgeAnalysis` | `资料分析.json` | `courses[]`、`runs[]` | 课程 → `points[]`（`id,no,title,level,keywords[],explain,analogy,formulas[],pitfalls[],examples[],sources[],generatedAt,model`）、`homework[]`、`ppt[]` |

### 枚举（显式白名单，非法值回落基线而不是报错）

| 字段 | 取值 |
|---|---|
| `tasks[].kind` | `homework` `lab` `report` `paper` `exam` `group` `other` |
| `tasks[].status` | `todo` `doing` `done` `dropped` |
| `tasks[].priority` | `low` `normal` `high`（面板接受「高/中/低」并映射） |
| `grades.rules.mode` | `4.0-weighted` `5.0-weighted`；`formula`：`linear-50` 等 |
| 紧急度（计算值） | `overdue` `today` `soon` `later` `done` `unknown` |
| `mastery` | `0` 未学 / `1` 学过 / `2` 熟练 / `3` 精通；上限 `MASTERY_MAX = 3` |

### id 规则

- 必须匹配 `/^[A-Za-z0-9_-]{1,64}$/`（`isValidId`）——同时也是**路径穿越的第二道防线**；
- 生成用 `makeId(prefix)`：`<prefix>_<base36 时间><6 位随机>`；
- 知识点 id 例外：`k_` + `sha1(课程id|节号|标题)` 前 10 位，**同一节同一标题恒同 id**，重跑不造重复。

### 字符串归一

`normalizeName`：trim、压空白、**截断 120 字**。
这条上限会影响业务：任务备注里同时要放 learn 去重记号与归档标记，因此归档时是「能塞末尾就塞末尾，塞不下把标记提前」。

## 七、dataDir 里不属于「十一份」的东西

| 路径 | 性质 | 会不会进备份包 / `/state` |
|---|---|---|
| `网络学堂.json` | **凭据**（会话 Cookie），刻意不在 `DOC_FILES` 白名单 | 都不进；原子写 + `mode 0o600` |
| `任务详情.json` | 平台作业详情缓存（TTL 3 分钟） | 不进（可重建） |
| `图片/_index.json` | 知识点插图白名单（`/materials/image` 的唯一依据） | 不进 |
| `讲解缓存/*.md` | 讲解结果缓存 | 不进 |
| `知识画布/` | 笔记镜像导出（只读视图，可随时重建） | 不进 |
| `备份/` | 每次覆盖写之前的旧版轮转 | 不进 |

**凭据三不原则**：不进白名单、不进 `/state`、不进任何响应体。`learnSessionSnapshot()` 不含 Cookie；
`readXxxConfig` / `writeXxxConfig` 集中管理、单独文件、`0o600`。

## 八、加新接口时必须守的规矩

1. **不建路由表**：在 GET 链或 POST 链里加一条 `if (rest === '…')`；`rest` 必须以 `/` 开头。
2. **绝不新增精确的 GET 之外的花式匹配**：唯一允许的通配是 `/lecture/<name>.js`；其它路径要么精确，要么不加。
3. **POST 的第一件事是 `writePreflight`**，不要自己重复查 origin；请求体一律走 `readJsonBody` / `readBody`。
4. **非 GET/POST 一律 405**，不要给某个路由单独放宽方法。
5. **新增数据文档**三选一：`DOC_KEYS` 全量白名单（走 `/state` 与 `/mutate`）／刻意白名单外（凭据类）／半白名单（在 `DOC_KEYS` 但不给 `DOC_ROUTES`，`/mutate` 回 `use-dedicated-route`）。
6. **绝不绕开 `store` 直接 `fs.writeFile`**：原子写、哈希、备份、冲突检查都在 store 里。
7. 写之前 `readDocument` 并区分 `missing` 与损坏：`if (!read.ok && read.reason !== 'missing') return 409`，否则用 `defaultDoc(key)`；**绝不在损坏文件上增量写，绝不把损坏当空数据重写**。
8. 写出的文档必须过 `validateDoc`；备份份数统一走 `deps.backupKeep`。
9. 错误必须是稳定 kebab-case，且**不抛异常**——handler 自己 `sendJson` 返回。
10. 新模块要进 `package.json` 的 `files`；要被 import 的消息还要进 `exports`。
11. **不在模块顶层或 handler 构造期起定时器 / 开进程**：由 `index.js` 用 `ctx.effect` 起并返回 `stop()`；可变状态放 handler 闭包（否则测试里每个用例都会漏一个 interval）。
12. 用户字符串进路径必须先过白名单或正则（`clientModulePath` 挡 `../../`，`path.resolve` 后还要确认仍在根下）。
13. 不把 Cookie / 凭据写进日志、响应体、错误 `detail`。
14. 新路由要同步在 `tests/host.test.js` 的路由清单断言里出现——它从 handler 源码反推路由列表，加了不注册会被测试抓出来。

## 九、契约自检

`npm test` 覆盖了契约的关键面（全部用 `node:test`，零依赖）：

- `tests/host.test.js`：从源码反推路由清单、`apply()` 注册个数、工具名与描述；
- `tests/http.test.js`：状态码、守卫顺序、批量更新原子性、损坏保护、备份往返；
- `tests/http-backup.test.js` / `tests/backup.test.js`：包格式、校验和、版本、拒绝写半截；
- `tests/http-knowledge-*.test.js`：讲解与问答的限额与失败码。

发布前跑一遍 `npm test`；要验「装进宿主之后还能不能跑」用 `npm run verify:installed`。
